# 1. ДЕКОМПОЗИЦИЯ ИГРЫ (что именно надо построить)

Игра состоит из 9 систем. Ниже — что делает каждая.

| # | Система | Суть |
|---|---|---|
| 1 | **Карта и рельеф** | Растровая сетка тайлов, 8 типов рельефа, города, столицы, мосты |

# 3. АРХИТЕКТУРА

## 3.1 Ключевой принцип: детерминированное ядро

```
src/

    balance.ts       # ВСЕ константы баланса
    rng.ts           # seeded PRNG (mulberry32 / xoshiro128**)
    types.ts
    world.ts         # World — вся сериализуемая структура матча
    terrain.ts       # сетка рельефа, стоимость прохода, модификаторы
    units.ts         # SoA-хранилище юнитов
    movement.ts      # следование по пути + локальное расталкивание
    combat.ts        # обнаружение контакта + формула урона
    influence.ts     # поле влияния, территория, связность снабжения
    economy.ts       # доход, содержание, снабжение, голод
    production.ts    # спавн из городов
    victory.ts       # условия победы
    sim.ts           # tick(world, commands) -> world'
    spatial.ts       # spatial hash grid
    pathfinding.ts   # A* по сетке рельефа (нужен ботам)
  ai/
    bot.ts           # фасад: думает, выдаёт Command[]
    perception.ts    # свёртка мира в стратегическую картину
    strategy.ts      # слой 1: цели матча (2 Гц)
    operations.ts    # слой 2: распределение армий по фронтам (4 Гц)
    tactics.ts       # слой 3: микро — цикл, атака-поверхность (каждый тик, лимит APM)
    profiles.ts      # уровни сложности
    debug.ts         # визуализация намерений бота
  render/
    camera.ts
    layers/terrain.ts     # кэш в offscreen canvas, перерисовка только при зуме
    layers/territory.ts   # цветные зоны + сглаженная граница фронта
    layers/units.ts       # батч-отрисовка точек
    layers/orders.ts      # линии приказов, лассо, превью пути
    layers/effects.ts     # тряска в бою, вспышки, дым
    minimap.ts
  ui/
    hud.ts, production-panel.ts, city-list.ts, menu.ts, endscreen.ts
  game/
    loop.ts          # фикс. timestep + интерполяция
```

## 3.2 Цикл симуляции

- **Фиксированный шаг**: 20 тиков в секунду (`TICK_MS = 50`). Вся логика — только внутри тика.
- **Рендер**: `requestAnimationFrame`, интерполяция позиций между тиками (`alpha`).
- **Аккумулятор** с защитой от «спирали смерти» (макс. 5 догоняющих тиков за кадр).
- Скорости игры 1× / 2× / 3× реализуются как N тиков за тот же реальный интервал, **не** изменением dt. Это сохраняет детерминизм.
- Никакого `Math.random()` — только `world.rng`.

`tick(world, commands: Command[]): void` — единственная точка мутации мира. Порядок внутри тика фиксирован:

```
1. applyCommands       (приказы игрока и ботов)
2. movement            (следование по путям, расталкивание, конверсия в корабли)
3. combat              (поиск контактов, урон, смерть)
4. regen               (HP/мораль с учётом близости врага и городов)
5. influence           (пересчёт поля влияния — не каждый тик, см. 4.6)
6. economy             (доход, содержание, снабжение, голод, окружение)
7. cityCapture         (смена владельца городов)
8. production          (спавн юнитов)
9. victory             (проверка условий)
```

## 3.3 Хранение юнитов

Structure-of-Arrays (типизированные массивы), не массив объектов:

```ts
interface UnitStore {
  count: number;
  capacity: number;
  id: Int32Array;
  owner: Uint8Array;        // 0 = нейтрал, 1..N = игроки
  kind: Uint8Array;         // 0 light, 1 heavy, 2 lightShip, 3 heavyShip
  x: Float32Array; y: Float32Array;
  vx: Float32Array; vy: Float32Array;
  hp: Float32Array;         // 0..1
  morale: Float32Array;     // 0..1
  pathIdx: Int32Array;      // индекс пути в PathPool, -1 = стоит
  pathPos: Float32Array;    // прогресс вдоль пути
  waterTime: Float32Array;  // сек. в воде (для конверсии в корабль)
  inCombat: Uint8Array;
  alive: Uint8Array;
  supplied: Uint8Array;
}
```

Свободные слоты переиспользуются (freelist). Никаких `splice` в горячем цикле.

# 4. ИГРОВЫЕ МЕХАНИКИ — ДЕТАЛЬНАЯ СПЕЦИФИКАЦИЯ

Все числа ниже — **стартовые значения для калибровки**, они живут в `balance.ts` и подбираются после плейтестов. Пометка 🎚 = обязательно вынести в ползунок дебаг-панели.

## 4.1 Карта и рельеф

Сетка тайлов, 1 тайл ≈ 4 игровых единицы. Типовая карта 256×256 тайлов, 4–8 городов.

Восемь типов рельефа:

| Тип | Скорость лёгких | Скорость тяжёлых | Урон лёгких | Урон тяжёлых | Прочее |
|---|---|---|---|---|---|
| `PLAINS` | 1.0 | 1.0 | 1.0 | 1.0 | — |
| `FOREST` | 1.0 | 0.55 | 1.0 | 0.35 | тяжёлые почти бесполезны |
| `HILLS` | 1.0 | 0.6 | 1.0 | 0.4 | как лес |
| `SAND` | 0.7 | 1.0 | 1.0 | 1.0 | тормозит только лёгких |
| `SNOW` | 0.85 | 0.85 | 0.75 | 0.75 | ослабляет всех |
| `MUD` | 0.7 | 0.6 | 0.75 | 0.75 | ослабляет всех |
| `WATER` | 0.35 | 0.3 | 0.5 | 0.5 | урон 0.02 HP/сек 🎚 |
| `MOUNTAIN` | — | — | — | — | **непроходимо** |

Города и мосты ведут себя как `PLAINS` и считаются безопасными.

**Формат карты:**
- `content/maps/<name>.png` — палитровая маска: цвет пикселя = тип рельефа (таблица соответствия в `terrain.ts`).
- `content/maps/<name>.json`:

```jsonc
{
  "id": "crossing",
  "name": "Переправа",
  "size": { "w": 256, "h": 256 },
  "terrainMask": "crossing.png",
  "players": 2,
  "cities": [
    { "id": "c1", "x": 40,  "y": 128, "capital": true,  "owner": 1, "radius": 6 },
    { "id": "c2", "x": 216, "y": 128, "capital": true,  "owner": 2, "radius": 6 },
    { "id": "c3", "x": 128, "y": 60,  "capital": false, "owner": 0, "radius": 5 }
  ],
  "startUnits": [
    { "owner": 1, "kind": "light", "count": 8, "x": 50, "y": 128, "spread": 12 },
    { "owner": 1, "kind": "heavy", "count": 2, "x": 50, "y": 140, "spread": 8 }
  ]

```

Загрузчик валидирует карту (столица у каждого игрока, нет юнитов в горах, все города достижимы) и падает с внятной ошибкой.

## 4.2 Юниты

| Параметр | Лёгкий | Тяжёлый |
|---|---|---|
| Цена | 200 | 400 |
| Базовый урон 🎚 | 1.0 | 2.2 |
| Макс. HP (эффективное) 🎚 | 1.0 | 1.8 |
| Скорость 🎚 | 1.0 | 0.65 |
| Радиус контакта | 3.0 | 3.6 |
| Инерция поворота 🎚 | низкая | высокая (тяжёлому трудно выйти из боя) |

Визуально: лёгкий — сплошной круг, тяжёлый — круг с кольцом/овалом внутри. Радиус чуть больше. Цвет = цвет игрока, яркость = HP.

**Корабли.** Юнит, находящийся в воде дольше `SHIP_CONVERT_SEC = 5` 🎚, превращается в корабельную форму: чуть быстрее по воде, но урон ×0.5 и продолжает получать урон от воды. Выйдя на сушу — конвертируется обратно через те же 5 секунд. Ходить по воде почти всегда плохо — это должно ощущаться в игре.

## 4.3 Бой

Бой начинается автоматически при контакте (расстояние ≤ сумме радиусов). Никаких приказов «атаковать» — только движение.

```
damage_per_sec =
    BASE_DAMAGE[kind]
  * healthFactor(hp)
  * moraleFactor(morale)
  * terrainDamageMod[terrain][kind]
  * (isMoving ? MOVING_PENALTY : 1.0)
```

- `healthFactor(hp) = Math.pow(hp, HEALTH_EXP)` — 🎚 `HEALTH_EXP = 0.5` (стартовое). Это делает раненых юнитов непропорционально ценными и порождает всю механику «цикла».
- `moraleFactor(m) = MORALE_FLOOR + (1 - MORALE_FLOOR) * m` — 🎚 `MORALE_FLOOR = 0.2`. Даже при нулевой морали юнит бьёт на 20%.
- 🎚 `MOVING_PENALTY = 0.9` — атакующий (движущийся) чуть слабее обороняющегося (стоящего). Маленький, но осмысленный бонус защиты.

**Правило одной цели:** юнит наносит урон только **одному** врагу — первому обнаруженному в контакте — даже если рядом трое. Это ключевая механика: она порождает понятие *attack surface* (побеждает тот, у кого в контакте больше юнитов). Не упрощай это до area-damage.

**Расход:**
- HP убывает пропорционально входящему урону.
- Мораль убывает с фиксированной скоростью, пока юнит в бою: 🎚 `MORALE_DRAIN = 0.06 /сек`.
- Смерть при `hp <= 0`.

## 4.4 Регенерация

| Условие | HP | Мораль |
|---|---|---|
| В бою | не регенерирует | −0.06/сек |
| Враг в радиусе `PROXIMITY_R = 12` 🎚 (но нет контакта) | **не регенерирует** | +0.10/сек 🎚 |
| Вне боя, врагов рядом нет | +0.010/сек 🎚 | +0.10/сек |
| То же, но внутри города | **+0.020/сек (×2)** | +0.10/сек |

Правило «враг рядом блокирует регенерацию HP» — не косметика: оно создаёт **издержку переключения** и делает микро-менеджмент цикла нетривиальным. Реализуй точно.

## 4.5 Экономика и снабжение

- Каждый город приносит 🎚 `CITY_INCOME = 12 ECO/сек`. Столица — ×1.5.
- Юнит **вне** города тратит 🎚 `UPKEEP = 1.5 ECO/сек`. Юнит **внутри** города — 0.
- Каждый город снабжает **5 юнитов** (🎚 `SUPPLY_PER_CITY = 5`).
- Если суммарно юнитов больше, чем `5 × (число городов в снабжающем кармане)` — избыток «голодает»: теряет 🎚 `STARVE_DPS = 0.03 HP/сек`. Голодают юниты с наименьшим HP последними (чтобы игрок терял не всё сразу) — или по выбору, вынеси стратегию в `balance.ts`.
- Баланс не может уйти в минус: при `ECO < 0` голодает вся армия.

## 4.6 Влияние, территория, окружение

Это самая нетривиальная и самая важная система. Она даёт три вещи сразу: красивую цветную карту, линию фронта и механику окружения.

**Алгоритм** (пересчёт раз в 5 тиков = 4 Гц, на огрублённой сетке ×4 от тайловой):

1. Источники влияния: города (сила `CITY_POWER = 100`, радиус большой) и юниты (сила `UNIT_POWER = 20`, радиус малый) 🎚.
2. **Многоисточниковый BFS/Dijkstra** по огрублённой сетке: от каждого источника распространяется убывающее значение, стоимость шага зависит от рельефа (горы = ∞, вода = дорого).
3. В каждой ячейке побеждает игрок с максимальным влиянием → `ownerGrid`. Ничья/нули → нейтраль.
4. **Связность снабжения**: для каждого игрока запусти flood-fill по его `ownerGrid`-ячейкам от его городов. Ячейки, до которых дошли, — «в снабжении». Юнит на несвязанной ячейке — **окружён**.
5. Окружённые юниты теряют 🎚 `ENCIRCLED_DPS = 0.08 HP/сек` — это в разы больше голода. Окружение должно убивать армии.
6. Окружённый карман, внутри которого есть свои города, работает как **отдельная экономика** (свой пул ECO, своё снабжение). Реализуй как `Pocket { playerId, cities[], units[], eco }`.

**Рендер территории:** записывай `ownerGrid` в `ImageData` низкого разрешения → `putImageData` на offscreen canvas → отрисовывай с масштабированием и лёгким размытием, чтобы граница получалась мягкой. Опционально: marching squares для чёткой линии фронта поверх заливки. Заливка — полупрозрачная (alpha ≈ 0.25), рельеф должен просвечивать.

## 4.7 Управление

| Действие | Ввод |
|---|---|
| Выделить юнита | ЛКМ |
| Выделить группу | ЛКМ + перетаскивание — **рисуем произвольное лассо** (не прямоугольник), замыкаем контур, берём всё внутри (point-in-polygon) |
| Добавить к выделению | Shift + ЛКМ / Shift + лассо |
| Задать путь | ПКМ + перетаскивание = **рисуем кривую**. Короткий клик ПКМ = прямая линия до точки |
| Стоп | `S` |
| Сбросить приказы | `C` |
| Выделить всех | `Ctrl+A` |
| Выделить всех тяжёлых / лёгких | `Ctrl+H` / `Ctrl+L` |
| Группы | `Ctrl+1..9` назначить, `1..9` выбрать |
| Пауза / скорость | `Space`, `+` / `-` |
| Камера | ПКМ по пустоте + драг, WASD, колесо = зум, край экрана |

**Рисование пути** — обязательно и критично. Игрок ведёт мышь, точки набираются с шагом (упрощение по Ramer–Douglas–Peucker), получается полилиния. Юниты идут по ней. При выделении нескольких юнитов путь применяется ко всем со смещением по нормали, чтобы они шли строем, а не гуськом.

**Локальное расталкивание:** юниты не должны накладываться. Простая сила отталкивания на основе spatial hash, без физдвижка. В бою расталкивание ослабляется (иначе фронт разъезжается).

## 4.8 Производство

Панель производства (как в оригинале), для каждого игрока:

- **Ползунок 1 — порог накопления.** Максимум: юнит появляется сразу, как накопилось 200 (400 для тяжёлого). Середина: ждём 2× цены. Минимум: производство фактически выключено. Формула: `threshold = cost * (1 + slider_inverse * K)` 🎚.
- **Ползунок 2 — доля тяжёлых, 0–100%.** Это **вероятность**, что очередной юнит будет тяжёлым. 0 = только лёгкие, 100 = только тяжёлые, 50 = поровну.
- **Города можно включать и выключать** кликом: выключенный город не производит, но продолжает давать доход и снабжать. Активные города соединены линиями (визуальная индикация).
- Спавн происходит в случайной точке внутри радиуса города (детерминированно, через `world.rng`).

## 4.9 Условия победы

По умолчанию (и как в референсе): **захватить вражескую столицу И контролировать ≥80% городов на карте.**

Сделай их конфигурируемыми в настройках матча:
- `CAPITAL_AND_MAJORITY` (по умолчанию)
- `ANNIHILATION` — уничтожить все вражеские юниты и города
- `TIMED_SCORE` — по истечении N минут побеждает тот, у кого больше очков (города ×10 + юниты ×1 + % территории)

Экран результата: длительность, произведено/потеряно юнитов, пик армии, захвачено городов, график экономики по времени.

# 5. ⭐ БОТЫ — ГЛАВНОЕ ОТЛИЧИЕ ПРОЕКТА

Это не «ИИ на отвали». Игра **целиком** держится на качестве ботов, потому что мультиплеера нет. Планируй сюда 40% усилий.

## 5.1 Железные правила

1. **Бот не жульничает.** По умолчанию он видит ровно то же, что игрок: позиции юнитов, HP-бары, города, территорию. Никакого доступа к внутренним намерениям игрока.
2. **Бот ограничен по APM.** У него есть бюджет действий в секунду. Он физически не может микрить всю армию идеально. Это главный регулятор сложности и главный источник ощущения «честного» противника.
3. **Бот думает с задержкой.** Реакция на новое событие приходит через `reactionDelayMs`, а не мгновенно.
4. **Ошибки — это фича.** Слабые боты должны совершать *правдоподобные* ошибки (переоценить силу, залезть в лес тяжёлыми, забыть про фланг), а не тупить случайным образом.

## 5.2 Трёхслойная архитектура

### Слой 1 — Стратегия (пересчёт 2 раза в секунду)

Свёртка мира в компактную картину:

```ts
interface StrategicView {
  cities: { id, owner, x, y, value, threat, myPressure, enemyPressure }[];
  fronts: Front[];            // кластеры контакта: где, кто, соотношение сил
  myArmy: { light, heavy, avgHp, avgMorale, supplyHeadroom };
  enemyArmy: { estLight, estHeavy, estStrength };  // оценка по видимому
  ecoRate: number;
  territoryShare: number;
}
```

Выбор макро-режима (взвешенный, с гистерезисом, чтобы не дёргаться):

| Режим | Когда | Что делает |
|---|---|---|
| `EXPAND` | есть нейтральные города, угроз нет | шлёт минимальные отряды к нейтралам, копит экономику |
| `DEFEND` | враг сильнее на 15%+ или давит на столицу | стягивает армию на выгодный рельеф, ставит тяжёлых на равнину, отдаёт территорию без городов |
| `PRESSURE` | примерный паритет | вяжет бои на выгодном рельефе, ждёт ошибки, копит преимущество |
| `PUSH` | преимущество 20%+ по силе или экономике | концентрирует силы на одном направлении, ломает фронт |
| `ENCIRCLE` | найден разрез, отсекающий врага от его городов | план захвата точки разреза |
| `SNIPE` | у врага слабо прикрыт город | быстрый рейд лёгкими |

**Оценка ценности города** = базовая + бонус за столицу + бонус за близость к моим городам + бонус за то, что он «разрезает» врага − штраф за расстояние − штраф за угрозу.

### Слой 2 — Операции (4 раза в секунду)

- Разбивает армию на **группы**: `frontline`, `reserve`, `garrison`, `raid`, `escort`.
- Распределяет юниты по фронтам пропорционально приоритету, с учётом рельефа: **тяжёлых — только на равнину/песок, никогда в лес и горы**; лёгкими держит лесистые направления.
- Держит **резерв** возле фронта (это делает возможным микро-цикл). Размер резерва ~30% от фронтовой группы 🎚.
- Ставит гарнизоны в города по формуле «риск потери × ценность».
- Планирует окружения: ищет на графе территории «узкие места» — ячейки, удаление которых из связности врага отсекает его юниты от его городов (по сути — поиск артикуляционных точек / min-cut на огрублённом графе). Если такая точка достижима и удержима — назначает операцию.

### Слой 3 — Тактика / микро (каждый тик, в пределах бюджета APM)

Действия в порядке приоритета — бот тратит бюджет сверху вниз:

1. **Цикл (cycling).** Отводить раненых, вводить свежих. Порог отвода 🎚 `cycleHpThreshold` (у сильных ботов ~0.75–0.85, у слабых ~0.35 — то есть слабые держат юнитов в бою слишком долго, что и есть типичная ошибка новичка). Отведённый юнит идёт в ближайший город или просто за радиус `PROXIMITY_R`, чтобы начать лечиться.
2. **Attack surface.** Подтягивать юниты так, чтобы в контакте было больше своих, чем чужих. Простое правило: не давать своим юнитам стоять «во втором ряду» без контакта, если можно обойти и вступить в бой.
3. **Не соваться в воду.** Жёсткий запрет, кроме явной операции с расчётом.
4. **Не бить тяжёлыми в лес.** Жёсткий запрет.
5. **Обход хвоста / фланг.** Если у врага открыт фланг — послать 2–3 лёгких в обход.
6. **Отвод обречённых.** Юнит с HP < 0.1 и без шанса выйти — отводить сразу.

### Слой 4 — Экономика бота

- Держит `ползунок порога` на максимуме, если снабжение позволяет; снижает при подходе к лимиту.
- Доля тяжёлых зависит от рельефа карты (много леса → мало тяжёлых) и от состава врага.
- Выключает производство в городах, которые вот-вот потеряет.

## 5.3 Профили сложности

```ts
interface BotProfile {
  name: string;
  apmBudget: number;        // действий в секунду
  reactionDelayMs: number;
  perceptionNoise: number;  // 0..1 — шум в оценке силы врага
  cycleHpThreshold: number;
  aggression: number;       // 0..1 — порог для PUSH
  planHorizonSec: number;
  usesEncirclement: boolean;
  usesTerrain: boolean;     // учитывает ли рельеф при позиционировании
  ecoEfficiency: number;    // 0..1 — насколько близко к оптимуму держит производство
  mistakeRate: number;      // 0..1 — шанс сознательно принять субоптимальное решение
}
```

| Профиль | APM | Задержка | Шум | Порог цикла | Окружения | Рельеф | Ошибки |
|---|---|---|---|---|---|---|---|
| Новобранец | 8 | 900 мс | 0.45 | 0.30 | нет | нет | 0.35 |
| Лейтенант | 20 | 550 мс | 0.30 | 0.50 | нет | да | 0.20 |
| Полковник | 45 | 300 мс | 0.18 | 0.70 | да | да | 0.10 |
| Генерал | 90 | 150 мс | 0.08 | 0.82 | да | да | 0.03 |
| Маршал | 160 | 80 мс | 0.03 | 0.85 | да | да | 0.00 |

Только на уровне «Маршал» разрешается **опциональный** экономический гандикап (×1.15 к доходу), и он должен быть явно подписан в UI. Никакого скрытого читерства.

## 5.4 Инструменты отладки ИИ (обязательно)

Клавиша `F3` включает оверлей бота:
- текущий макро-режим и его «очки» относительно альтернатив;
- фронты, их приоритет и соотношение сил;
- принадлежность юнитов к группам (цветные обводки);
- целевые города со стрелками;
- планируемая точка окружения;
- бюджет APM: потрачено/доступно;
- лог решений за последние 10 секунд.

Плюс режим `?bots=only` — бот против бота на ускорении ×3 для быстрой калибровки баланса. И CLI-режим `npm run sim -- --map crossing --a general --b colonel --games 100`, который прогоняет матчи без рендера и печатает винрейт. Это твой главный инструмент тюнинга.

# 6. РЕНДЕР И ВИЗУАЛЬНЫЙ СТИЛЬ

Минимализм — это не «лень», это осознанная эстетика. Референс настроения: штабная карта, а не игрушка.

- Фон: очень тёмный (`#0e1116`) или очень светлый (`#f2efe9`, «бумага»). Сделай обе темы.
- Рельеф — приглушённые заливки, разница между типами читается, но не кричит. Горы — заметно темнее/светлее, чтобы мгновенно читались как стены.
- Территория — полупрозрачная заливка цветом игрока поверх рельефа. Граница фронта — сплошная линия 2px.
- Юниты — круги 4–7 px. Тяжёлые с внутренним кольцом. Полоска HP — тонкая дуга или подложка, появляется при HP < 100%.
- Бой — юнит мелко дрожит (детерминированное дрожание от `tick` и `id`, не от `Math.random`).
- Цвета игроков: синий `#4a90d9`, красный `#d94a4a`, зелёный, янтарный. Дальтоник-режим — разная форма маркера столицы.
- **Никаких** спрайтов, текстур, скинов, шейдеров на старте.

Производительность (бюджет на кадр, 600 юнитов):
- симуляция ≤ 4 мс/тик
- рендер ≤ 8 мс/кадр
- стабильные 60 fps на интегрированной графике
- слой рельефа рисуется в offscreen-канвас и перерисовывается только при смене зума

# 7. КАЧЕСТВО И ТЕСТЫ

Тесты обязательны для `core/` и `ai/`:

- **Детерминизм**: два прогона одного матча с одинаковым seed и одинаковым списком команд дают **побитово** одинаковый хеш `world` через 5000 тиков. Это самый важный тест в проекте — он падает первым, когда кто-то занесёт `Math.random()`.
- **Бой**: 3 лёгких против 2 лёгких на равнине — побеждают трое, с предсказуемым остатком HP. Тяжёлый в лесу проигрывает лёгкому.
- **Регенерация**: юнит в 11 единицах от врага не лечится; в 13 — лечится; в городе — вдвое быстрее.
- **Экономика**: 6 юнитов на 1 город → один голодает.
- **Окружение**: юнит, отрезанный от городов, теряет HP по `ENCIRCLED_DPS`.
- **Карман**: отрезанная группа с собственным городом живёт на своей экономике.
- **Победа**: срабатывает ровно при захвате столицы + 80% городов, не раньше.
- **Пути**: RDP-упрощение сохраняет форму кривой в пределах допуска.
- **Влияние**: изменение владельца города меняет `ownerGrid` в ожидаемых пределах.

Плюс бенчмарк `npm run bench`: 600 юнитов, 1000 тиков, печатает мс/тик — падает, если превысили бюджет.

# 8. ПЛАН ФАЗ

Каждая фаза заканчивается рабочей, играбельной сборкой и коммитом.

**Фаза 0 — Каркас.** Vite + TS + Vitest + ESLint. Фикс-timestep цикл с интерполяцией. Камера (пан, зум, границы). Debug-оверлей (fps, тик, мс/тик).
*Приёмка:* пустая карта, камера летает, 60 fps, счётчики честные.

**Фаза 1 — Рельеф и карты.** Формат карты, загрузчик PNG-маски + JSON, валидатор, 8 типов, кэширующий рендер рельефа, 2 тестовые карты.
*Приёмка:* карта грузится и рисуется, горы визуально читаются как стены.

**Фаза 2 — Юниты и движение.** SoA-хранилище, spatial hash, спавн, лассо-выделение, рисование кривых путей, следование, расталкивание, модификаторы скорости от рельефа, `S`/`C`/группы.
*Приёмка:* 300 юнитов выделяются лассо, идут по нарисованной кривой строем, не слипаются, обходят горы, тонут в темпе воды. 60 fps.

**Фаза 3 — Бой.** Обнаружение контакта, правило одной цели, формула урона, мораль, HP, правило близости, регенерация, смерть, дрожание в бою.
*Приёмка:* тесты боя зелёные; тест детерминизма зелёный; глазами видно, что «больше юнитов в контакте = выигрываешь».

**Фаза 4 — Города, экономика, влияние.** Города, столицы, захват, доход, содержание, снабжение, голод, поле влияния, территория, связность, окружение, карманы.
*Приёмка:* захват города перекрашивает территорию; окружённая армия тает; отрезанный карман живёт на своих городах.

**Фаза 5 — Интерфейс матча.** HUD (ECO, армия, снабжение, таймер), панель производства с двумя ползунками, вкл/выкл городов, миникарта, пауза, скорости 1×/2×/3×, экран победы.
*Приёмка:* можно сыграть полный матч против «болванчика», который просто копит и идёт вперёд.

**Фаза 6 — ⭐ Боты.** Все четыре слоя, 5 профилей, F3-оверлей, headless-режим `npm run sim`.
*Приёмка:* Полковник обыгрывает Лейтенанта в ≥70% из 100 headless-матчей; Генерал обыгрывает Полковника в ≥70%; ни один бот не делает грубых ошибок из списка «жёстких запретов» (тяжёлые в лесу, армия в воде).

**Фаза 7 — Оболочка.** Главное меню, настройка схватки (карта, число ботов, сложность каждого, команды: 1v1 / 1v2 / 2v2 / FFA до 4), условия победы, настройки (тема, дальтоник-режим, громкость, чувствительность камеры), сохранение настроек в `localStorage`.
*Приёмка:* можно настроить и сыграть 2v2 с ботом-союзником.

**Фаза 8 — Полировка.** Реплеи (seed + журнал команд, воспроизведение с перемоткой), процедурный звук через WebAudio (без файлов), эффекты, туториал из 4 шагов, локализация RU/EN.
*Приёмка:* реплей матча воспроизводится идентично исходному.

**Фаза 9 — Опционально (обсудить отдельно).** Редактор карт в браузере, кампания из связанных боёв, тач-управление, WebGL-рендер.
