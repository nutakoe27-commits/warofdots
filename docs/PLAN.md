# План работ по фазам

Нормативный документ — `docs/SPEC.md`. Здесь — разбивка на фазы, чек-листы и
критерии приёмки. Отметка ✅ ставится только когда критерий проверен, а не когда
код написан.

Проверка на каждой фазе: `npm run verify` (= `typecheck` + `lint` + `test`).

---

## Фаза 0 — Каркас ✅

- [x] Vite + TypeScript (`strict`, `noUncheckedIndexedAccess`) + Vitest + ESLint + Prettier
- [x] `npm run verify` собран одной командой
- [x] Цикл с фиксированным шагом 20 Гц и интерполяцией (`src/game/loop.ts`)
- [x] Аккумулятор с защитой от спирали смерти (`MAX_CATCHUP_TICKS`)
- [x] Камера: панорама, зум к курсору, ограничение по краям карты (`src/render/camera.ts`)
- [x] Дебаг-оверлей: fps, мс/тик, мс/кадр, тики за кадр, хеш мира (`src/ui/debug-panel.ts`)
- [x] Линтер запрещает `Math.random` / `Date.now` / DOM в `src/core` и `src/ai`

**Приёмка.** Пустая карта, камера летает, 60 fps, счётчики честные. ✅

## Фаза 1 — Рельеф и карты ✅

- [x] Формат карты: JSON + либо процедурный рецепт, либо палитровая PNG-маска (ADR-003)
- [x] Загрузчик и валидатор: столица у каждого игрока, юниты не в горах, все города достижимы
- [x] 8 типов рельефа, таблицы скорости / урона / стоимости пути на тип юнита
- [x] Кэширующий рендер рельефа (offscreen, 1 пиксель на тайл, один `drawImage` за кадр)
- [x] Четыре карты: `crossing`, `thicket`, `highlands`, `quadrant` (2p / 2p / 2p / 4p)
- [x] `npm run map:png` выгружает карту в PNG для доработки руками

**Приёмка.** Карта грузится и рисуется, горы визуально читаются как стены. ✅

## Фаза 2 — Юниты и движение ✅

- [x] SoA-хранилище с переиспользованием слотов через freelist
- [x] Spatial hash (подсчитывающая сортировка, перестройка дважды за тик — ADR-014)
- [x] Пул путей со счётчиком ссылок: приказ на 300 юнитов — один `Float32Array`
- [x] Лассо произвольной формы (point-in-polygon), Shift для добавления
- [x] Рисование кривой ПКМ, короткий клик — прямая; упрощение по Ramer–Douglas–Peucker
- [x] Строй через боковые смещения от осевой линии пути (ADR-016)
- [x] Локальное расталкивание, ослабленное в бою
- [x] Модификаторы скорости от рельефа, скольжение вдоль гор
- [x] Конверсия в корабль и обратно через `SHIP_CONVERT_SEC`
- [x] `S` / `C` / `Ctrl+A` / `Ctrl+H` / `Ctrl+L` / группы `Ctrl+1..9` и `1..9`

**Приёмка.** 300 юнитов выделяются лассо, идут по нарисованной кривой строем, не
слипаются, обходят горы, тонут в темпе воды, 60 fps. ✅

## Фаза 3 — Бой ✅

- [x] Обнаружение контакта по сумме радиусов
- [x] **Правило одной цели**, урон считается одновременно через аккумулятор
- [x] Формула урона: HP, мораль, рельеф, штраф за движение
- [x] Мораль: слив в бою, восстановление вне
- [x] Правило близости врага блокирует регенерацию HP
- [x] Регенерация вдвое быстрее в городе
- [x] Смерть, освобождение слота и пути
- [x] Дрожание в бою от `(tick, id)`, не от `Math.random`

**Приёмка.** Тесты боя зелёные, тест детерминизма зелёный, «больше юнитов в
контакте — выигрываешь» видно глазами. ✅

## Фаза 4 — Города, экономика, влияние ✅

- [x] Города, столицы, захват по присутствию, включение/выключение производства
- [x] Доход, множитель столицы, содержание, освобождение от содержания в городе
- [x] Лимит снабжения на город и голод избытка (стратегия настраиваема — ADR-013)
- [x] Многоисточниковый Dijkstra по огрублённой сетке, полоса ничьей (ADR-008)
- [x] Территория, связность снабжения, окружение — из одного прохода
- [x] Карманы как компоненты территории; казна на городах (ADR-004)
- [x] Отрезанный карман со своими городами живёт на своей экономике

**Приёмка.** Захват города перекрашивает территорию; окружённая армия тает;
отрезанный карман живёт на своих городах. ✅

## Бюджеты производительности

Проверяются `npm run bench` (симуляция) и панелью `F4` (рендер).

| Бюджет | Цель | Как проверить |
|---|---|---|
| Симуляция | ≤ 4 мс/тик при 600 юнитах | `npm run bench` |
| Рендер | ≤ 8 мс/кадр | `F4`, строка `мс/кадр` |
| Кадры | стабильные 60 fps | `F4`, строка `fps` |
